> **النسخة:** 1.1
> **الغرض:** **المصدر الوحيد للحقيقة** لكل قاعدة عمل في المنصة. كل قاعدة لها رمز ثابت يُشار إليه في الكود والاختبارات والوثائق.
> **مكان الملف:** `docs/06-business-rules.md`
> **يعتمد على:** `01` إلى `05`، وقرارات `11-decisions.md` (v1.1)

## 1. كيف تُستعمل هذه الوثيقة

### 1.1 صيغة القاعدة

لكل قاعدة: **رمز**، **نص** بصيغة قاطعة، **مكان الإنفاذ**، و**رمز الخطأ** عند المخالفة.

**اصطلاح الرموز:** `BR-<المجال>-<رقم>` مثل `BR-DONOR-06`.
**النجمة ★** بعد الرمز تعني قاعدة **حرجة** (خصوصية أو صلاحيات أو سلامة بيانات): فشلها يوقف الإطلاق.

### 1.2 أماكن الإنفاذ

| الاختصار | المكان | المرجع |
|---|---|---|
| **DB** | قيد أو فهرس أو مفتاح في قاعدة البيانات | `02-database.md` |
| **SCH** | مخطط Pydantic (التحقق والتطبيع) | `05`، القسم 8 |
| **DEP** | `api/deps.py` (الجلسة، الصلاحية، MFA، CSRF) | `05`، القسم 7 |
| **POL** | وحدة `policy` (النطاق والحالة) | `03` |
| **SVC** | طبقة الخدمات | `05`، القسم 12 |
| **CLI** | أمر خارج HTTP | `05`، القسم 17 |
| **UI** | عقد عرض على الواجهة (تُوثَّق هنا لكنها لا تُنفَّذ في الخلفية) | |

> **مبدأ الدفاع المتعدد:** القاعدة الحساسة تُنفَّذ في **أكثر من مكان** (مثل SCH + SVC + DB). يُذكر كل مكان.

### 1.3 قواعد استعمال الوثيقة

1. **لا قاعدة في الكود بلا رمز هنا.** وإن اكتُشفت قاعدة في الكود فتُضاف هنا أولًا.
2. **التعليق في الكود** يذكر الرمز (مثل `# BR-CONSENT-03`).
3. **كل قاعدة لها اختبار** اسمه يحمل الرمز (انظر `07`).
4. **تعديل قاعدة** = تعديل هذه الوثيقة، ثم الاختبار، ثم الكود (بهذا الترتيب).
5. إن تعارضت قاعدة هنا مع وثيقة أخرى، **تُعتمد هذه الوثيقة** وتُصحَّح الأخرى (القسم 17 يسجّل ما يلزم تصحيحه).

## 3. الحملات (CAMP)

### 3.1 الحالات والانتقالات

```
        open                      end
upcoming ───► live ─────────────► ended ───(بعد سنة)──► ended + purged
    ▲           │                   │
    └─ revert ──┘                   └─ لا عودة إلى live أبدًا
   (بشرط: لا متبرعين)
```

| الرمز | القاعدة | الإنفاذ | الخطأ |
|---|---|---|---|
| **BR-CAMP-01** | تُنشأ الحملة بحالة `upcoming` وغير منشورة وغير حالية | SVC | |
| **BR-CAMP-02** | `slug` لاتيني صغير وأرقام وشرطات (`^[a-z0-9]+(-[a-z0-9]+)*$`) وفريد | SCH + DB | `slug_taken` |
| **BR-CAMP-03** ★ | **النشر:** الحملة غير المنشورة غير مرئية للعامة، وتُعامل كأنها غير موجودة (`404`) في كل النقاط العامة (المحتوى، العدّادات، الأبطال، الترتيب، الصور) | SVC | `not_found` |
| **BR-CAMP-04** | **حملة حالية واحدة كحد أقصى** | DB (فهرس جزئي) + SVC | |
| **BR-CAMP-05** | **تعيين الحالية:** لحملة **منشورة** فقط، في معاملة واحدة (إلغاء السابقة ثم تعيين الجديدة) | SVC | `campaign_closed` |
| **BR-CAMP-06** ★ | **`open` (قادمة ← جارية):** تتطلب أن تكون الحملة منشورة، ولها موقع مشارك واحد على الأقل، وليست منتهية، **ولا توجد حملة أخرى جارية**. وتُعيَّن تلقائيًا حملةً حالية (ضمن المعاملة نفسها) | SVC | `invalid_state_transition` |
| **BR-CAMP-07** | **حملة جارية واحدة فقط** في أي وقت (المشرفون يعملون على "الحملة الجارية") | SVC | `invalid_state_transition` |
| **BR-CAMP-08** | **`revert` (جارية ← قادمة):** مسموحة **فقط** إن لم يُسجَّل أي متبرع في الحملة، وتتطلب تأكيدًا حديثًا | SVC + DEP | `invalid_state_transition` |
| **BR-CAMP-09** ★ | **`end` (جارية ← منتهية):** معاملة واحدة: (1) حساب الأرقام النهائية، (2) تخزينها في `final_stats`، (3) الحالة `ended` و`ended_at`، (4) تدقيق `campaign.end`. تتطلب أدمن بـ MFA وتأكيدًا حديثًا | SVC + DEP | `invalid_state_transition` |
| **BR-CAMP-10** | **إعادة `end` على حملة منتهية** تُحدّث `final_stats` (للتصحيح)، **ما لم تُخفَ هويتها** | SVC | `campaign_purged` |
| **BR-CAMP-11** | الحملة المنتهية **لا تعود** جارية | SVC | `invalid_state_transition` |
| **BR-CAMP-12** ★ | **إلغاء النشر** ممنوع والحملة جارية. وإلغاء نشر الحملة الحالية يُلغي كونها حالية | SVC | `invalid_state_transition` |
| **BR-CAMP-13** | **الحذف:** فقط إن لم يوجد أي تعهد أو متبرع أو صورة | SVC + DB | `in_use` |
| **BR-CAMP-14** | **تاريخ الحملة:** إلزامي، ويُمنع تعديله بعد أن تصبح الحملة جارية (لأنه أساس حساب مدة الحفظ) | SVC | `invalid_state_transition` |
| **BR-CAMP-15** | `content` بصيغة Markdown حتى 100 كيلوبايت، يُخزَّن كنص خام ويُحوَّل إلى HTML في الخادم بمكتبة Markdown متبوعة بمكتبة تعقيم HTML مجرّبة مع تفعيل `autoescape` في القوالب. يُمنع منعًا باتًا قبول أو عرض أي وسم أو كود HTML خام من المستخدم (D-70) | SCH + SVC | `validation_error` |
| **BR-CAMP-16** ★ | **الكتابة الميدانية** (إضافة/تعديل/حذف متبرعين وصور من المشرف) مسموحة **فقط** والحملة `live` | POL | `no_live_campaign` / `campaign_not_live` |
| **BR-CAMP-17** | بعد `end` **لا يُعطَّل المشرفون تلقائيًا**. التعطيل خطوة إدارية مقصودة (الأمر الجماعي)، لكنهم يفقدون القراءة والكتابة فورًا بحكم BR-CAMP-16 | SVC | |
| **BR-CAMP-18** | تعديل الأدمن لبيانات حملة منتهية (مثل تصحيح متبرع) **يجب أن يُتبع بإعادة `end`** لتحديث الأرقام المجمّدة | SVC (توثيق/تنبيه) | |

## 6. المتبرعون (DONOR)

### 6.1 الحالات

```
(إضافة) ──► attended  ◄────────►  donated
            (حضر)        (تبرّع ✓ / تراجع)
```

| الرمز | القاعدة | الإنفاذ | الخطأ |
|---|---|---|---|
| **BR-DONOR-01** ★ | المتبرع يُنشئه **مشرف** في موقعه (والحملة جارية) أو **أدمن**. ولا يُنشئه الزائر أبدًا | DEP + POL | `forbidden` |
| **BR-DONOR-02** ★ | **الاشتقاق من السياق:** `campaign_id` = الحملة الجارية، و`site_id` = موقع المشرف، و`registered_by` = المشرف. ولا يُقبل أي منها من الجسم | SVC + SCH | `unknown_field` |
| **BR-DONOR-03** | الحالة الابتدائية دائمًا `attended` | SVC | |
| **BR-DONOR-04** | `first_name` 1–40 حرفًا. `last_name` اختياري حتى 40. `blood_type` اختيارية من الفصائل الثمان | SCH + DB | `validation_error` |
| **BR-DONOR-05** | **معرّف العميل:** إن أرسل العميل `id` (UUID) فهو معرّف السجل. **إعادة الإرسال** بالمعرّف نفسه بالمحتوى نفسه من المشرف والموقع والحملة نفسها ← `200` مع السجل نفسه (آمنة التكرار بلا إنشاء مكرر). أما إذا أُرسل المعرّف نفسه بمحتوى مختلف (حتى من المشرف نفسه) أو لموقع/حملة أخرى ← `409 duplicate_id_conflict` | SVC | `duplicate_id_conflict` |
| **BR-DONOR-06** | **تغيير الحالة** مسموح في الاتجاهين (`attended ⇄ donated`) | SVC | |
| **BR-DONOR-07** | **`donated_at`:** تُملأ عند الانتقال إلى `donated` وتُمحى عند الرجوع إلى `attended`. تملؤها **الخدمة** (لا مشغّل) | SVC + DB (CHECK) | |
| **BR-DONOR-08** ★ | **لا توجد حالة "مرفوض" ولا أي حقل يُظهر سبب عدم التبرع.** من حضر ولم يُسمح له طبيًا يبقى `attended` ولا يُعلَن ذلك لأحد (صيانة للكرامة) | تصميم | |
| **BR-DONOR-09** ★ | المشرف يقرأ ويكتب **متبرعي موقعه فقط**. المورد خارج نطاقه ← **`404`** لا `403` | POL + SVC | `not_found` |
| **BR-DONOR-10** ★ | المشرف **لا يغيّر** `site_id` ولا `campaign_id` ولا `registered_by` ولا `anonymized_at` لأي سجل | SVC + SCH | `unknown_field` |
| **BR-DONOR-11** | **حذف المتبرع:** للمشرف (موقعه، الحملة جارية) لتصحيح الخطأ، وللأدمن في أي وقت بتأكيد حديث. يُحذف معه صوره الفردية وتُضاف ملفاتها لطابور الحذف | SVC | |
| **BR-DONOR-12** ★ | **نقل متبرع** لموقع آخر: للأدمن فقط بتأكيد حديث، والموقع الهدف مشارك في **الحملة نفسها**. وتُنقل **صوره الفردية** معه في المعاملة نفسها | SVC + DB | `site_not_in_campaign` |
| **BR-DONOR-13** | **تنبيه التكرار (ناعم):** `check-phone` يخبر إن كان الهاتف مسجَّلًا في الموقع والحملة نفسيهما، **دون منع** (قد يتشارك أفراد رقمًا) | SVC | |
| **BR-DONOR-14** ★ | **الهاتف لا يظهر في القوائم**، بل في **تفاصيل** المتبرع فقط (للمشرف في موقعه وللأدمن) | SCH | |
| **BR-DONOR-15** | المتبرع **المخفي الهوية** (`anonymized_at` ليس فارغًا) **للقراءة فقط** ولا يُعدَّل | SVC | `campaign_purged` |
| **BR-DONOR-16** | تعديل بيانات المتبرع (للمشرف) مسموح والحملة جارية. وللأدمن في أي وقت ما لم يكن مخفي الهوية | POL + SVC | |
| **BR-DONOR-17** | **البحث السريع** للمشرف بالاسم الأول أو الأخير (بداية الاسم، غير حساس للحالة) داخل موقعه فقط | SVC | |
| **BR-DONOR-18** | يُسجَّل تدقيق لكل: إنشاء، تغيير حالة، تعديل (أسماء الحقول فقط)، حذف، نقل | SVC | |
