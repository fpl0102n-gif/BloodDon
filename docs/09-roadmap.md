# 09 - خطة البناء (Roadmap)

> **النسخة:** 1.1 (محدّثة ومتزامنة مع `06` v1.1 و `05` v1.1 و `11-decisions.md` v1.1)
> **الغرض:** ترتيب بناء المنصة (الخلفية وقوالب الويب) في **مراحل صغيرة**، لكل مرحلة مخرجات وقواعد واختبارات ومعيار قبول واضح، مع خط قطع لما يمكن تأجيله إن ضاق الوقت.
> **مكان الملف:** `docs/09-roadmap.md`
> **يعتمد على:** `05` (ترتيب الطبقات وقوالب الويب)، `06` (القواعد)، `07` (الاختبارات)، `08` (الإعداد)، وقرارات `11-decisions.md`
> **يرتبط بـ:** `10-testing-security-deployment.md` و `12-implementation-plan.md`

**نوع الوثيقة:** خطة، لا تتضمن شيفرة.

---

## 1. مبادئ الخطة

| المبدأ | المعنى |
|---|---|
| **الأخطر أولًا** | المصادقة والصلاحيات تُبنى قبل أي ميزة، لأن كل ما بعدها يعتمد عليها |
| **شريحة رأسية** | كل مرحلة تُنتج شيئًا **يعمل ويُختبر من طرفه إلى طرفه**، لا طبقات ناقصة |
| **الاختبار قبل الاعتماد** | لا تُعدّ مرحلة منتهية إلا باجتياز **كل الاختبارات الحرجة (★)** لقواعدها |
| **القواعد قبل الكود** | أي غموض يُحسم في `06` و`07` أولًا، ثم يُكتب الكود |
| **مرحلة واحدة في كل مرة** | لا بدء مرحلة قبل إغلاق سابقتها (إلا المسارات غير التقنية الموازية) |
| **خط قطع صريح** | ما يُؤجَّل إن ضاق الوقت معروف مسبقًا (القسم 6) |
| **تقديرات تقريبية** | مطوّر منفرد؛ تُراجَع بعد المرحلتين الأوليين على ضوء السرعة الفعلية |

### المرحلة 1: الأساس (2–3 أيام) ← **M1**

**الهدف:** تطبيق يقلع ويستجيب، بكل البنى المشتركة، دون أي ميزة عمل.

**المخرجات**
- `core/`: الإعدادات مع **فشل الإقلاع بسر ناقص في `prod`**، الاتصال بالقاعدة، اتفاقية التسمية، الأخطاء النطاقية، التسجيل مع **حجب البيانات الحساسة**، الوقت (`Clock`)، هيكل تحديد المعدل.
- `api/`: وسطاء (request-id، ترويسات الأمان، IP الموثوق، فحص Origin)، معالج الأخطاء الموحّد، `/health` و`/ready`.
- **مخطط أساسي** `extra=forbid` وأنواع مشتركة (الهاتف، الفصيلة، الصفحة).
- بنية الاختبار: `conftest`، معاملة لكل اختبار، الأدوار الجاهزة (هيكل)، `Clock`/`Storage`/`Mailer` مزيّفة، علامات `critical` و`br`.
- **الاختبار المعماري** (قواعد الاعتماد).

**القواعد:** BR-GEN-04، 05، 06 (الآلية)، 09، 10 (الآلية)، BR-RATE-10 (قراءة IP).

**الاختبارات المطلوبة:** `T-STRUCT-04`، `T-STRUCT-08` (جزئيًا)، `T-STRUCT-10` (آلية الحجب)، `T-GEN-04-a`، `T-GEN-05`، `T-RATE-10-a/b`.

**معيار القبول**
- [ ] `/health` و`/ready` يعملان، و`/docs` تُعطَّل بإعداد `prod`.
- [ ] الإقلاع في `prod` بلا سر **يفشل برسالة واضحة**.
- [ ] أي استثناء نطاقي يُحوَّل إلى الشكل الموحّد برمز و`request_id`.
- [ ] اختبار الحجب: قيمة خفر (هاتف/كلمة مرور) لا تظهر في السجل.
- [ ] الاختبار المعماري يفشل عند استيراد مخالف (يُجرَّب عمدًا).
- [ ] ترويسات الأمان حاضرة.

**المخاطر/البديل:** لا مخاطر كبرى. لا تُهمل الاختبار المعماري هنا، فبناؤه لاحقًا أصعب.

### المرحلة 3: المصادقة والصلاحيات (6–8 أيام) ← **M2** (أعلى المخاطر)

**الهدف:** دخول آمن للمشرفين والأدمن، وإطار صلاحيات تُبنى عليه كل المراحل التالية.

**الخطوات الداخلية (تُغلق بالترتيب)**

| الخطوة | المحتوى |
|---|---|
| **3a** | المستخدم، تجزئة argon2، الدخول، رسالة موحّدة وتساوي العمل، القفل، الجلسات (إنشاء، فحص كل طلب، مدد، إبطال)، الكوكي |
| **3b** | الدعوة وإعادة التعيين، `Mailer`، رموز بالهاش، أمر `create-admin` |
| **3c** | MFA: TOTP، منع إعادة الاستعمال (`totp_last_used_step`)، أكواد الاسترداد، تشفير السر |
| **3d** | `policy`: الرموز والمصفوفة و`can()`، `require(...)`، **CSRF**، **التأكيد الحديث (R)** |
| **3e** | هيكل **اختبار المصفوفة** و**اختبار تغطية المسارات** على المسارات الموجودة |
| **3f** | `/me` (كلمة المرور، MFA، الخروج من الكل) |

**القواعد:** BR-AUTH-01 إلى 19، BR-USER-01 إلى 04، 08 (الآلية)، BR-RATE-01/02/06/07/09، BR-AUDIT (أحداث المصادقة).

**الاختبارات المطلوبة:** كل `T-AUTH-*`، `T-USER-03/04`، `T-RATE-01/02/06/07/09`، `T-STRUCT-01/02/03`، `T-GEN-07-b`.

**معيار القبول**
- [ ] **كل** حالات AUTH الحرجة (★) ناجحة، بما فيها: القفل، تساوي الرسالة، تجديد الجلسة عند الدخول، الإبطال بكل المحفّزات الستة، CSRF، التأكيد الحديث.
- [ ] تجربة يدوية كاملة: `create-admin` ← تفعيل MFA ← دعوة مشرف ← قبول الدعوة ← دخوله ← تعطيله ← سقوط جلسته فورًا.
- [ ] اختبار المصفوفة يعمل على المسارات المتاحة، واختبار التغطية يكسر البناء عند مسار بلا صلاحية.
- [ ] لا كلمة مرور أو رمز أو سر MFA في أي سجل (قيم خفر).
- [ ] مراجعة ذاتية سطرًا بسطر لكل ملفات `core/security.py` و`services/auth.py` و`services/sessions.py` و`api/deps.py`.

**المخاطر/البديل**
- **الخطر الأعلى في المشروع** (مصادقة مكتوبة يدويًا). تُلتزم المكتبات المجرّبة، ولا يُخترع تشفير.
- **إن تجاوزت المرحلة 150% من تقديرها:** تُراجَع الخطة: (أ) تأجيل MFA للمشرفين (أصلًا اختيارية)، (ب) استبدال جزء بمكتبة جلسات/مصادقة مجرّبة بدل كتابته، (ج) **لا تُخفَّف** قواعد القفل والإبطال والتأكيد الحديث.

### المرحلة 4: الإدارة الأساسية (4–5 أيام)

**الهدف:** أن يستطيع الأدمن تجهيز حملة كاملة عبر API.

**المخرجات**
- المواقع: إضافة، تعديل، تعطيل، حذف مشروط.
- الحملات: إنشاء، تعديل، نشر، **تعيين الحالية**، **`open`**، **`revert`**، حذف مشروط.
- مشاركة المواقع في الحملة (الوقت، فريق الإشراف).
- إدارة المستخدمين: دعوة، تعديل، تعطيل/تفعيل، فك قفل، إعادة MFA، إعادة إرسال الدعوة، **التعطيل الجماعي**.
- `AuditService` وعرض `GET /admin/audit`.
- إدارة الصور العامة (غلاف وشعار) بمعالجة الصور الأساسية.

**القواعد:** BR-CAMP-01 إلى 08، 11 إلى 15، BR-SITE-*، BR-CSITE-*، BR-USER-05 إلى 10، BR-AUDIT-01 إلى 05، BR-GEN-11/12.

**الاختبارات المطلوبة:** `T-CAMP` (عدا 09، 10، 17، 18)، `T-SITE`، `T-CSITE`، `T-USER`، `T-AUDIT`، `T-CONC-02/03`، وصفوف الأدمن من المصفوفة، `T-GEN-12-b`.

**معيار القبول**
- [ ] سيناريو يدوي (httpie/Postman) يجهّز حملة كاملة: مواقع ← حملة ← مشاركات ← نشر ← تعيين حالية ← `open` ← دعوة مشرفين.
- [ ] كل انتقال حالة غير مسموح يرد `invalid_state_transition`.
- [ ] حملة جارية واحدة حتى تحت التزامن.
- [ ] كل عملية حساسة تتطلب R وتُدوَّن بلا بيانات شخصية.
- [ ] **OpenAPI الأولي** صالح، ويمكن تسليمه للواجهة (بداية المسار الموازي).

**المخاطر/البديل:** تعقيد المعاملات (`open`، `set_current`) ← اختبارات التزامن مبكرًا.

### المرحلة 8: الإنهاء والاحتفاظ (4–5 أيام) ← **M5**

**الهدف:** إغلاق دورة الحياة: تجميد الأرقام، وحماية الخصوصية بعد سنة.

**المخرجات**
- **`end`** (ومعاملة واحدة) وإعادته للتصحيح.

- **إخفاء الفرد فورًا** (حق الانسحاب) وحذف التعهد/الرقم بطلب صاحبه.
- **نقل متبرع** بين المواقع (مع صوره الفردية).
- حذف ملفات الطابور (أمر أو نقطة إدارية).
- تعطيل المشرفين بعد الحملة (جاهز من P4).

**معيار القبول**
- [ ] **سيناريو دورة الحياة مؤتمت:** `open` ← متبرعون ← `end` ← الأرقام مجمّدة ← المشرف يفقد الوصول ← (ساعة مزيّفة +366 يومًا) ← `purge` ← الأرقام والترتيب والأبطال والمعرض سليمة ← الهواتف والفصائل والتعهدات والصور الفردية زالت.
- [ ] `purge` **آمن التكرار** (مرتان بلا تغيير)، و`--dry-run` لا يغيّر شيئًا.
- [ ] فشل حملة واحدة في `purge` لا يوقف الأخرى.
- [ ] **الإنهاء ذرّي** (فشل مُحقَن لا يترك حالة وسطى).
- [ ] تجربة `purge` على نسخة من قاعدة بيانات التجربة قبل أي بيانات حقيقية.

### المرحلة 11: التكامل والبروفة والقبول (5–7 أيام) ← **M7**

## 9. العمل مع المساعد البرمجي

> إن كنت ستبني بمساعد برمجي (Claude Code أو غيره)، هذه الأسس تحميك من الاندفاع في كل الاتجاهات.

### 9.1 قواعد

| # | القاعدة |
|---|---|
| 1 | **مرحلة واحدة في كل جلسة.** أعطه `CLAUDE.md` + قسم المرحلة من هذه الوثيقة + الأقسام ذات الصلة فقط من `02/03/04/06/07` |
| 2 | **الاختبارات أولًا:** يكتب حالات `07` الخاصة بالخطوة ثم الكود الذي يجعلها تنجح |
| 3 | **ترتيب داخلي ثابت:** نموذج + هجرة ← مخطط ← مستودع ← خدمة ← صلاحية ← router ← اختبارات (`05` القسم 21) |
| 4 | **خطوة صغيرة، دمج صغير:** نقطة وصول أو قاعدة واحدة في كل مرة، و`make check` بعد كل خطوة |
| 5 | **لا تعديل صامت للقواعد.** إن اكتشف غموضًا يتوقف ويقترح تعديل `06`/`07`، فتوافق أنت ثم يُنفَّذ |
| 6 | **مراجعة الفرق (diff)** بحثًا عن الأنماط الممنوعة (`05` القسم 19): `site_id` من الجسم، `commit` في خدمة، تسجيل هاتف... |
| 7 | **المناطق الحساسة** (المصادقة، الموافقات، الطوارئ، الإخفاء): **مراجعة يدوية سطرًا بسطر**، ولا تُدمج بمجرد نجاح الاختبارات |
| 8 | **اطلب منه تشغيل** `T-STRUCT-05` لاكتشاف قواعد بلا اختبار |
| 9 | **لا مكتبات جديدة** دون موافقتك |
| 10 | **لا أسرار ولا بيانات حقيقية** في أي محادثة أو ملف |

### 9.2 قالب بدء مرحلة (مرجعي)

> «نعمل الآن على **المرحلة N: <الاسم>**. اقرأ `CLAUDE.md` وقسم المرحلة في `docs/09-roadmap.md` والقواعد المذكورة في `docs/06-business-rules.md`. ابدأ بكتابة الاختبارات المدرجة للخطوة <x> من `docs/07-test-cases.md`، ثم نفّذ الحد الأدنى لتمريرها، دون الخروج عن بنية `docs/05-architecture.md`. توقف وأخبرني عند أي غموض في القواعد بدل افتراضه. بعد الانتهاء شغّل `make check`.»

### 9.3 تحذيرات
- **لا يُعتمد على نجاح الاختبارات وحدها** في الموافقات والصلاحيات: الاختبار الناقص يمرّر كودًا خطرًا.
- **سرعة الكتابة لا تلغي المراجعة:** وقت المراجعة جزء من التقدير.
- **حدّث الوثائق مع الكود** (تعريف الاكتمال)، وإلا فسدت المرجعية.

## 14. ملخص

- **الخطة المعتمدة:** 16 أسبوعًا تجمع بين خلفية FastAPI وقوالب واجهة Jinja2 (W1–W6) لمطوّر منفرد.
