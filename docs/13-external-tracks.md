## 1. الهدف من الوثيقة

أغلب أسباب تعطل أو تأخر منصات التبرع بالدم لا تأتي من الكود البرمجي، بل من **المسارات الخارجية والاعتمادات الإدارية والطبية والقانونية**.
هذه الوثيقة هي **سجل الحقيقة الواحد (Single Source of Truth)** لتتبع:
1. **بوابات الانطلاق والقرارات الخارجية (G1 إلى G8)**.
2. **المسارات الموازية الستة (A إلى F)** المحددة في `docs/09-roadmap.md` §5.
3. **تحديد المسؤولين (Owners)، المواعيد النهائية (Deadlines)، والأدلة المادية المطلوبة للاكتمال**.

## 3. تفاصيل المسارات الموازية

### المسار A: مركز الدم والشراكة الطبية (G6)
- **الهدف:** ضبط الضوابط الطبية بما يحمي المتبرعين والمرضى قانونيًا وطبيًا.
- **المسؤول:** منسق العلاقات مع مركز الدم (ممثل النادي الطبي).
- **المهام والمخرجات:**
  1. [ ] **قيمة أيام الراحة بعد التبرع (`D-37`):** تحديد `EMERGENCY_MIN_DAYS_SINCE_DONATION` (القيمة الافتراضية 0 حتى يحددها المركز رسميًا؛ المقترح الطبي المعتاد 60–90 يومًا).
  2. [ ] **نص الموافقات الشفهية:** مراجعة واعتماد صياغة الموافقات الأربع (`consent_keep_phone`، `consent_hero_name`، `consent_photo`، `consent_public_phone`).
  3. [ ] **رقم هاتف مركز الدم:** اعتماده ليظهر في صفحة الطوارئ والاستفسارات الطبية.
  4. [ ] **معلومات التبرع وشروط الأهلية:** اعتماد النص العربي التوعوي الذي يظهر للزوار في صفحة المعلومات.
  5. [ ] **اتفاقية الشراكة والتمثيل:** إشعار إدارة المركز بآلية تسجيل المتبرعين عبر المنصة.

### المسار B: الخصوصية والمراجعة القانونية (G7)
- **الهدف:** الالتزام الصارم بحماية المعطيات الشخصية الحساسة وعدم التعرض لمساءلة نظامية.
- **المسؤول:** مسؤول الامتثال القانوني / رئيس النادي الطبي.
- **المهام والمخرجات:**
  1. [ ] **تحديد مسؤول معالجة البيانات خطيًا (`D-66`):** توثيق الجهة القانونية المسؤولة عن معالجة بيانات المتبرعين (النادي الطبي بالشراكة مع مركز الدم).
  2. [ ] **المراجعة القانونية لصيغ الموافقات (`D-67`):** التأكد من مطابقة آلية الموافقة المستقلة الصريحة لقوانين حماية البيانات المحلية.
  3. [ ] **سياسة الخصوصية وشروط الاستخدام:** صياغة سياسة الخصوصية المعروضة على المنصة وإجراءات إخفاء البيانات بعد عام (`BR-PRIV-*`).
  4. [ ] **تعهد السرية للمشرفين:** صياغة نموذج التزام المشرف الميداني بعدم تصوير أو تسريب أرقام المتبرعين خارج نطاق المنصة.

### المسار C: الهوية والمحتوى والوسائط
- **الهدف:** تجهيز الواجهة العامة بهوية بصرية احترافية وجذابة دون أي روابط أو مراجع خارجية (قرار `D-71`).
- **المسؤول:** فريق الإعلام والتصميم بالنادي الطبي.
- **المهام والمخرجات:**
  1. [ ] **اسم الحملة وشعارها الرسمي (`D-04`):** تحديد الاسم الرسمي للحملة وتجهيز الشعار بصيغتي SVG/PNG مدمجة محليًا.
  2. [ ] **الوسوم والهاشتاغ الموحد:** لاقتباسه في رسائل المشاركة وحملات التواصل.
  3. [ ] **صورة المعاينة لشبكات التواصل (Open Graph Image):** تصميم صورة بأبعاد 1200×630 لعرضها عند مشاركة الرابط عبر واتساب وتيليغرام وفيسبوك.
  4. [ ] **شعارات الشركاء والرعاة:** تنظيف وضغط شعارات المركز والنادي لتضمينها محليًا في `app/web/static/`.

### المسار D: البنية التحتية والحسابات التشغيلية (G2, G3, G4, G8)
- **الهدف:** تجهيز بيئات التطوير والـ Staging والإنتاج في التوقيت المناسب دون تعريض الأسرار للخطر.
- **المسؤول:** المطوّر التقني / مهندس العمليات (DevOps).
- **المهام والمخرجات:**
  1. [x] **البيئة المحلية:** Docker Compose + PostgreSQL 16 + Mailpit + أدوات التطوير (`P0.7`, `P0.8`, `P0.9`, `P0.10`, `P0.11`, `P0.12`).
  2. [x] **تأكيد المنطقة الزمنية (`G2`):** اعتماد `APP_TIMEZONE = Africa/Algiers` رسميًا ومطابقتها لـ `.env.example`.
  3. [x] **حساب PostgreSQL المُدار (`G3`):** تجهيز بيئة Staging المحلية (`db_staging` بورت 5434)، وسكربتات تهيئة الأدوار السحابية (`init-managed-db.sql`)، وأداة التدقيق الآلي `verify-database` للتحقق التلقائي من الصلاحيات و SSL وهجرات Alembic ومطابقتها لـ 12 اختبار وحدة (المسؤول: المطوّر التقني).
  4. [x] **خدمة SMTP والنطاق (`G4`):** ربط وتوثيق وسيط البريد Resend وإجراء اختبار إرسال ناجح وتوثيقه (المسؤول: المطوّر التقني).
  5. [ ] **خادم VPS مع Caddy (`G8`):** حجز خادم VPS وتشغيل وسيط Caddy الآمن بشهادات TLS التلقائية قبل المرحلة P10 (المسؤول: المطوّر التقني).

### المسار E: الفريق البشري والتدريب الميداني
- **الهدف:** جاهزية الكوادر الميدانية والإدارية لتشغيل المنصة بسلاسة في يوم الحملة.
- **المسؤول:** منسق العمليات الميدانية بالنادي الطبي.
- **المهام والمخرجات:**
  1. [ ] **تسمية الأدمن الأساسي والاحتياطي:** توفير أدمنين اثنين على الأقل وتفعيل MFA لهما فور إنشاء الحسابات.
  2. [ ] **تسمية المشرفين الميدانيين وتوزيعهم:** تعيين مشرف لكل موقع (مع مشرف احتياطي لكل موقع).
  3. [ ] **أوراق التسجيل والموافقات الاحتياطية:** طباعة نماذج ورقية مطابقة للمنصة للطوارئ القصوى وانقطاع الشبكة.
  4. [ ] **جلسة تدريبية ومحاكاة ميدانية:** تدريب المشرفين في المرحلة P11 على شاشات الإدخال والتعامل مع حالات المتبرعين.
