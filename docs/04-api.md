## 1. ما الذي تغيّر عن النسخة السابقة

| كان (Supabase) | أصبح |
|---|---|
| دوال RPC (`submit_pledge`، `get_ranking`...) | نقاط REST بمسارات واضحة تحت `/api/v1/public/...` |
| جداول تُقرأ وتُكتب مباشرة من المتصفح | **لا وصول مباشر لأي جدول.** كل شيء عبر نقاط API |
| المشرف يرسل `site_id` و`campaign_id` | **ممنوع.** تُشتق من المستخدم والسياق (انظر `03`، القسم 13) |
| أخطاء قاعدة البيانات الخام | **عقد أخطاء موحّد** برموز ثابتة (القسم 3) |
| `reveal_donor_phone` | `POST /public/emergency/donors/{id}/reveal` |
| `end_campaign` | `POST /admin/campaigns/{id}/end` |

## 2. الاتفاقيات العامة

| البند | الاتفاق |
|---|---|
| **المسار الأساسي** | `/api/v1` (الواجهة والـ API تحت نطاق واحد، قرار D-13) |
| **التنسيق** | JSON بترميز UTF-8. الاستثناء الوحيد: رفع الصور `multipart/form-data` |
| **أسماء الحقول** | `snake_case` إنجليزي |
| **المعرّفات** | UUID. والحملة العامة تُعرَّف بـ `slug` |
| **الوقت** | ISO 8601 بتوقيت UTC (`2026-11-20T18:00:00Z`) |
| **الحالات** | قيم إنجليزية ثابتة (`attended`، `donated`، `upcoming`، `live`، `ended`) |
| **الفصائل** | `A+` `A-` `B+` `B-` `AB+` `AB-` `O+` `O-` |
| **الهاتف** | يُقبل بأرقام عربية-هندية وفراغات وشرطات ويُطبَّع في الخادم إلى `+?` وأرقام لاتينية (8 إلى 15 رقمًا) |
| **الحقول الزائدة** | **تُرفض** (`422`)، فلا يُقبل أي حقل غير معرّف في الـ Schema |
| **الحقول المحجوزة** | `id` (للمتبرع فقط اختياري)، `status` ابتدائية، `donated_at`، `registered_by`، `site_id`/`campaign_id` (للمشرف)، `role`: محاولة إرسالها تُرفض وتُسجَّل في التدقيق كمحاولة مشبوهة |
| **تنظيف النصوص** | قص الفراغات من الأطراف، ورفض المحارف التحكمية |
| **اللغة** | الرسائل التقنية بالإنجليزية، **والواجهة هي التي تترجم الرموز إلى رسائل عربية** (القسم 3.3) |
| **التوثيق** | OpenAPI تلقائي من FastAPI. صفحة `/docs` **معطّلة في الإنتاج** أو محمية بدخول الأدمن |

### 2.1 الترويسات

| الترويسة | الاتجاه | الاستعمال |
|---|---|---|
| `X-Request-ID` | استجابة (وطلب اختياري) | معرّف تتبع يظهر في الأخطاء والسجلات |
| `X-CSRF-Token` | طلب | **إلزامية** لكل `POST/PUT/PATCH/DELETE` المصادَق عليها بكوكي (تُجلب من `GET /auth/csrf`) |
| `Cache-Control` | استجابة | بحسب القسم 5 |
| `Retry-After` | استجابة | مع `429` |
| `Idempotency` | | لا ترويسة خاصة؛ المتبرع يحمل `id` من العميل (القسم 9.2) |

### 2.2 رموز HTTP المستعملة

| الرمز | الاستعمال |
|---|---|
| `200` | نجاح قراءة أو تحديث بمخرجات |
| `201` | إنشاء بمخرجات |
| `204` | نجاح بلا مخرجات |
| `401` | لا جلسة أو منتهية |
| `403` | غير مصرّح، أو `mfa_required`، أو `reauth_required`، أو `csrf_failed` |
| `404` | غير موجود **أو خارج النطاق** |
| `409` | تعارض مع الحالة الحالية (حملة ليست جارية، انتقال حالة غير مسموح، تكرار، قيد مرجعي) |
| `413` | ملف كبير |
| `415` | نوع ملف غير مدعوم |
| `422` | فشل التحقق من المدخلات |
| `429` | تجاوز المعدل |
| `500` | خطأ غير متوقع |
| `503` | الميزة معطّلة مؤقتًا بمفتاح إيقاف (مثل `EMERGENCY_ENABLED=false` أو `PLEDGES_ENABLED=false`) |

## 3. عقد الأخطاء

### 3.1 الشكل الموحّد

```json
{
  "error": {
    "code": "phone_requires_consent",
    "message": "Phone number cannot be stored without consent.",
    "details": [ { "field": "phone", "issue": "requires_consent" } ],
    "request_id": "b2f1c0de-..."
  }
}
```

- `code`: ثابت ومعتمد، تبني عليه الواجهة والاختبارات.
- `message`: تقني للمطوّر، **لا يُعرض للمستخدم**.
- `details`: اختياري، لأخطاء الحقول (`422`).
- `request_id`: للربط بالسجلات.
- **لا** أسماء جداول، ولا أخطاء SQL، ولا تتبّع (stack trace).

### 3.2 فهرس الرموز

| الرمز | HTTP | المعنى |
|---|---|---|
| `validation_error` | 422 | مدخل غير صالح (التفاصيل في `details`) |
| `unknown_field` | 422 | حقل غير معرّف أو محجوز |
| `phone_requires_consent` | 422 | هاتف بلا موافقة حفظ أو نشر |
| `public_phone_requires_data` | 422 | موافقة نشر الرقم بلا هاتف أو فصيلة |
| `invalid_image` | 422 | الملف ليس صورة صالحة |
| `photo_consent_missing` | 422 | صورة فردية لمتبرع لم يوافق على الصورة |
| `not_authenticated` | 401 | لا جلسة |
| `session_expired` | 401 | انتهت الجلسة |
| `invalid_credentials` | 401 | بيانات الدخول خاطئة (موحّد لكل أسباب الفشل) |
| `forbidden` | 403 | لا صلاحية |
| `mfa_required` | 403 | الجلسة لم تُتحقق بالمصادقة الثنائية |
| `reauth_required` | 403 | تأكيد حديث بكلمة المرور مطلوب |
| `csrf_failed` | 403 | رمز CSRF مفقود أو خاطئ |
| `not_found` | 404 | غير موجود أو خارج النطاق |
| `campaign_closed` | 409 | الحملة لا تقبل هذه العملية (غير منشورة أو منتهية) |
| `campaign_not_live` | 409 | الحملة ليست جارية |
| `no_live_campaign` | 409 | لا توجد حملة جارية حاليًا |
| `campaign_already_ended` | 409 | الحملة منتهية |
| `campaign_purged` | 409 | بياناتها الشخصية أُخفيت ولا تُعدَّل |
| `invalid_state_transition` | 409 | انتقال حالة غير مسموح به (مثل إنهاء حملة غير جارية، فتح جارية مع وجود أخرى، إعادة جارية بها متبرعون، إلغاء نشر جارية، تعديل تاريخ جارية) |
| `site_not_in_campaign` | 409 | الموقع غير مشارك في الحملة |
| `duplicate_id_conflict` | 409 | معرّف المتبرع مستعمل بسجل مختلف |
| `slug_taken` | 409 | `slug` مستعمل |
| `email_taken` | 409 | البريد مستعمل |
| `in_use` | 409 | لا يمكن الحذف لوجود بيانات مرتبطة |
| `last_admin` | 409 | لا يمكن تعطيل آخر أدمن نشط أو النفس |
| `invalid_token` | 400 | رمز الدعوة أو إعادة التعيين غير صالح أو منتهٍ أو مستعمل |
| `file_too_large` | 413 | الحجم يتجاوز الحد |
| `unsupported_media_type` | 415 | النوع غير مدعوم |
| `rate_limited` | 429 | تجاوز المعدل |
| `service_unavailable` | 503 | الميزة معطّلة بمفتاح إيقاف (`EMERGENCY_ENABLED` أو `PLEDGES_ENABLED`) |
| `internal_error` | 500 | خطأ غير متوقع (يُسجَّل داخليًا) |

## 4. التقسيم إلى صفحات والتصفية

| البند | القاعدة |
|---|---|
| **الشكل** | `{ "items": [...], "total": 120, "limit": 25, "offset": 0 }` |
| **المعاملات** | `limit` (الافتراضي 25، **الحد الأقصى 100**)، `offset` (الافتراضي 0) |
| **الحد الأقصى المانع للتجميع** | لا يوجد `limit=all`. وهذا جزء من مبدأ **"لا تصدير"** (قيمة أكبر من الحد تُرفض بـ `422`) |
| **الترتيب** | افتراضي لكل مورد (مذكور في وصفه)، و`sort` مسموح بقيم محددة فقط |
| **البحث** | `q` نصي بسيط (بداية الاسم، غير حساس للحالة) |
| **التصفية** | معاملات صريحة لكل نقطة (`status`، `site_id`، `blood_type`...) |

> **استثناء:** القوائم الصغيرة بطبيعتها (ترتيب النوادي، المواقع المشاركة، نتائج الطوارئ) تُرجع كل عناصرها ضمن حد ثابت داخلي.

## 5. التخزين المؤقت وتحديد المعدل

| النوع | `Cache-Control` | أمثلة |
|---|---|---|
| **عام مؤقت قصير** | `public, max-age=30` | العدّادات، الترتيب، الأبطال |
| **عام أطول** | `public, max-age=300` | الحملات، المواقع، المنشورات |
| **ممنوع التخزين** | `no-store` | كل ما هو مصادَق عليه، **وصفحة الطوارئ بالكامل** |

**تحديد المعدل:** الجدول الكامل في `03-auth-permissions.md` (القسم 15). ملخص:

| النقطة | الحد |
|---|---|
| `POST /auth/login` | 10 / 15 دقيقة لكل IP + قفل الحساب |
| `POST /public/campaigns/{slug}/pledges` | 20 / ساعة |
| `GET /public/emergency/donors` | 60 / ساعة |
| `POST /public/emergency/donors/{id}/reveal` | 10 / ساعة |
| `POST /auth/password/forgot` | 5 / ساعة |

عند التجاوز: `429` + `Retry-After` + الرمز `rate_limited`.

# الجزء الأول: النقاط العامة (بلا حساب)

> **الصلاحية:** لا شيء، لكن **تُطبَّق قيود النشر**: الحملة `is_published`، والموقع `is_active`. الحملة غير المنشورة تُعامل كأنها غير موجودة (`404`).

## 6. المحتوى العام

### 6.1 `GET /public/campaigns/current`
الحملة الحالية (`is_current` ومنشورة). `404` إن لم توجد.

**المخرجات:** كائن الحملة العام (القسم 12.1).

### 6.2 `GET /public/campaigns`
قائمة الحملات المنشورة، الأحدث تاريخًا أولًا.

| المعامل | الوصف |
|---|---|
| `status` | `upcoming` / `live` / `ended` |
| `year` | سنة التاريخ |
| `limit`، `offset` | الصفحات |

**المخرجات:** صفحة من بطاقات الحملات (العنوان، `slug`، الغلاف، التاريخ، الحالة، المقتطف). **لا `content`** كاملًا في القائمة.

### 6.3 `GET /public/campaigns/{slug}`
صفحة الحملة كاملة (مع `content` Markdown **المنظَّف عند العرض في الواجهة**، والخادم يخزّنه كما هو). إن كانت منتهية تُرجَع `final_stats`.

### 6.4 `GET /public/campaigns/{slug}/sites`
المواقع المشاركة مع تفاصيلها وعدد المهتمين.

**المخرجات (لكل عنصر):** `site_id`، `name`، `logo_url`، `address`، `map_url`، `start_time`، `end_time`، `supervisors_text`، `description`، `pledges_count`.

### 6.5 `GET /public/campaigns/{slug}/counters`
**المخرجات:**
```json
{ "pledges_count": 143, "present_count": 61, "donated_count": 52, "heroes_count": 38 }
```
**القاعدة:** حملة منتهية لها `final_stats` ← الأرقام المجمّدة. وإلا تُحسب مباشرة. `Cache-Control: public, max-age=30`.

### 6.6 `GET /public/campaigns/{slug}/heroes`
| المعامل | الوصف |
|---|---|
| `site_id` | تصفية اختيارية |
| `limit` (حتى 200)، `offset` | الصفحات |

**القاعدة:** `donated` **و** `consent_hero_name`. الأحدث تبرعًا أولًا.
**المخرجات:** `first_name`، `site_id`، `site_name` **فقط**.

### 6.7 `GET /public/campaigns/{slug}/ranking`
**المخرجات (مرتبة):** `rank`، `site_id`، `site_name`، `logo_url`، `donors_count`.
**القواعد:**
1. العدّ يشمل من لم يوافق على الظهور (أرقام مجمّعة)، والمواقع الصفرية تظهر، والتعادل يمنح المرتبة نفسها (1، 1، 3)، والترتيب الثانوي بالاسم.
2. **الحملة المنتهية (`status = 'ended'`):** تؤخذ أرقام الترتيب مباشرة من البيانات المجمّدة في `c.final_stats->'by_site'` مع ربطها بجدول `sites` لجلب أحدث اسم وشعار للموقع (`BR-RANK-05`)، ولا يُستعلم جدول `donors` للحملات المنتهية.

### 6.8 `GET /public/campaigns/{slug}/photos`
**المعاملات:** `site_id` اختياري، `limit`، `offset`.
**المخرجات:** `id`، `url`، `caption`، `site_id`، `kind`. **الصور الفردية** لا تظهر إلا لحملة منشورة (والموافقة محققة عند الرفع).

### 6.9 `GET /public/sites`
قائمة المواقع النشطة (للصفحات التعريفية).

### 6.10 المنشورات الحرة *(إن اعتُمد `posts`، قرار D-01)*
- `GET /public/posts` (قائمة، `limit`/`offset`).
- `GET /public/posts/{slug}`.

> **صفحات "معلومات التبرع" و"التواصل والتطوع":** محتوى ثابت (انظر D-22). **لا نقطة API** لنموذج التطوع في النسخة الأولى؛ يُكتفى بروابط واتساب/بريد، فلا تُخزَّن بيانات إضافية.

## 7. نيّة الحضور

### 7.1 `POST /public/campaigns/{slug}/pledges`

| | |
|---|---|
| **الصلاحية** | `pledge:create` |
| **الحدّ** | 20 / ساعة لكل IP |
| **الحماية** | حقل honeypot (`website`) يجب أن يكون فارغًا، وإلا يُرجع `204` **دون حفظ** (لا يُخبَر الروبوت) |

**الجسم:**
```json
{ "site_id": "…", "first_name": "أحمد", "phone": "0550 00 00 00", "website": "" }
```

| الحقل | إلزامي | قواعد |
|---|---|---|
| `site_id` | نعم | يجب أن يكون الموقع مشاركًا في الحملة |
| `first_name` | نعم | 2 إلى 40 حرفًا |
| `phone` | لا | يُطبَّع، 8–15 رقمًا |
| `website` | لا | honeypot |

**القواعد:**
1. **مفتاح الإيقاف (`PLEDGES_ENABLED`):** إن كانت قيمة الإعداد `false` في البيئة، تُرَد النقطة بـ `503 service_unavailable` (قرار D-62، `BR-PLEDGE-01`).
2. الحملة منشورة وحالتها `upcoming` أو `live`، وإلا `409 campaign_closed`.
3. الموقع مشارك في الحملة، وإلا `409 site_not_in_campaign`.
4. **تكرار الهاتف** في الموقع والحملة نفسيهما **لا ينشئ سجلًا ولا يُظهر خطأً**.
5. **الرد متطابق** في حالتي السجل الجديد والمكرر (`204`) كي لا يُسرَّب أن رقمًا مسجَّل.

**المخرجات:** `204 No Content`.
**الأخطاء:** `422 validation_error`، `409`، `429`، `503 service_unavailable`.

## 8. الطوارئ ("أحتاج دمًا")

> كل استجابات هذه الفقرة: `Cache-Control: no-store`.
> **مفتاح الإيقاف (`EMERGENCY_ENABLED`):** إن كانت قيمة الإعداد `false` في البيئة، تُرَد جميع نقاط الطوارئ بـ `503 service_unavailable` (قرار D-62، `BR-EMERG-01`).

### 8.1 `GET /public/emergency/donors`

| المعامل | إلزامي | الوصف |
|---|---|---|
| `blood_type` | **نعم** | إحدى الفصائل الثمانية |
| `site_id` | لا | تصفية بالموقع |

**القاعدة:** `consent_public_phone` **و** `status = donated` **و** الهاتف موجود **و** لم تُخفَ الهوية **و** مرّ على التبرع ما لا يقل عن `EMERGENCY_MIN_DAYS_SINCE_DONATION` يومًا (الافتراضي 0، قرار D-37، `BR-EMERG-11`). الأقدم تبرعًا أولًا، **حتى 50 نتيجة**.

**المخرجات (لكل عنصر):**
```json
{ "donor_id": "…", "first_name": "سارة", "blood_type": "O+", "site_name": "نادي الطب أ", "days_since_donation": 140 }
```
**لا هاتف في هذه الاستجابة إطلاقًا.**

### 8.2 `POST /public/emergency/donors/{donor_id}/reveal`

| | |
|---|---|
| **الصلاحية** | `emergency:reveal` |
| **الحدّ** | 10 / ساعة لكل IP (هاش مملَّح) |
| **لماذا POST؟** | له أثر جانبي (تسجيل) ولا يجوز تخزينه مؤقتًا |

**المخرجات:**
```json
{ "phone": "+213550000000" }
```
**القواعد:** يُرجع الرقم فقط إن تحققت شروط النشر كلها، وإلا `404 not_found` (**لا نميّز** بين غير موجود وغير موافق). يُسجَّل الطلب في `phone_reveal_log`، وحدث تدقيق `emergency.reveal` بالمعرّف فقط.
**الأخطاء:** `404`، `429`، `503 service_unavailable`.

# الجزء الثاني: المصادقة والحساب

## 9. نقاط المصادقة (`/auth`)

| النقطة | الوصف | الصلاحية |
|---|---|---|
| `GET /auth/csrf` | يعيد رمز CSRF للجلسة الحالية (أو لجلسة مجهولة قبل الدخول) | عامة |
| `POST /auth/login` | دخول بالبريد وكلمة المرور | عامة (محدودة المعدل) |
| `POST /auth/mfa/verify` | التحقق من رمز TOTP أو كود استرداد | جلسة مرحلية |
| `POST /auth/reauth` | تأكيد حديث بكلمة المرور (ورمز MFA للأدمن) | مسجّل |
| `POST /auth/logout` | خروج من الجلسة الحالية | مسجّل |
| `POST /auth/logout-all` | خروج من كل الأجهزة | مسجّل |
| `POST /auth/password/forgot` | طلب إعادة تعيين | عامة (محدودة المعدل) |
| `POST /auth/password/reset` | تعيين كلمة جديدة برمز | عامة |
| `POST /auth/invite/accept` | قبول دعوة وتعيين كلمة المرور | عامة |

### 9.1 `POST /auth/login`
**الجسم:** `{ "email": "...", "password": "..." }`

**المخرجات عند النجاح:**
```json
{ "user": { "id": "…", "full_name": "…", "role": "supervisor", "site_id": "…" },
  "mfa_required": false }
```
- إن كان `mfa_required = true`: تُنشأ جلسة **مرحلية** (`mfa_verified = false`) ولا يُسمح بغير `/auth/mfa/verify`.
- تُضبط كوكي الجلسة. وتُنشأ جلسة **جديدة** دائمًا.

**الأخطاء:** `401 invalid_credentials` (لكل أسباب الفشل **بنفس الرد والزمن**)، `429`.

### 9.2 `POST /auth/mfa/verify`
**الجسم:** `{ "code": "123456" }` أو `{ "recovery_code": "…" }`.
**القواعد:** 5 محاولات للجلسة المرحلية ثم إبطالها. الرمز لا يُقبل ثانية خلال نافذته. كود الاسترداد يُستهلك.
**المخرجات:** نفس مستخدم الدخول مع `mfa_verified = true`.

### 9.3 `POST /auth/reauth`
**الجسم:** `{ "password": "…", "code": "123456" }` (الرمز للأدمن).
**الأثر:** يحدّث طابع "آخر تأكيد" في الجلسة. **المخرجات:** `204`.

### 9.4 `POST /auth/password/forgot`
**الجسم:** `{ "email": "…" }`
**الرد دائمًا `204`** سواء وُجد الحساب أم لا (ولا يتغير الزمن). إن وُجد حساب نشط يُرسَل رابط صلاحيته ساعة.

### 9.5 `POST /auth/password/reset`
**الجسم:** `{ "token": "…", "new_password": "…" }`
**القواعد:** الرمز استعمال واحد، فإن صلح تُعيَّن الكلمة ويُبطَل **كل** جلسات المستخدم ويُصفَّر عدّاد الفشل. MFA يبقى مطلوبًا.
**الأخطاء:** `400 invalid_token`، `422` (كلمة ضعيفة).

### 9.6 `POST /auth/invite/accept`
**الجسم:** `{ "token": "…", "password": "…" }`
**القواعد:** الرمز من نوع `invite` صالح غير مستعمل. تُعيَّن الكلمة ويُفعَّل الحساب. للأدمن: تُوجَّه الواجهة لشاشة تفعيل MFA فورًا.
> الرمز يُرسَل في **الجسم** لا في المسار، حتى لا يظهر في سجلات الخوادم.

# الجزء الثالث: واجهة المشرف (`/supervisor`)

> **الشروط العامة لكل ما يلي:** حساب مشرف نشط (A)، **موقع المشرف** هو النطاق (S)، **والحملة جارية** (L). الحملة تُشتق: هي الحملة **الحالية الجارية**. إن لم توجد: `409 no_live_campaign`.
> **ممنوع** إرسال `site_id` أو `campaign_id` أو `registered_by` أو `status` ابتدائية (يُرفض بـ `422 unknown_field` ويُدوَّن).

## 11. السياق والمتبرعون

### 11.1 `GET /supervisor/context`
لتهيئة لوحة المشرف.
```json
{ "campaign": { "id": "…", "title": "…", "status": "live" },
  "site": { "id": "…", "name": "نادي الطب أ" },
  "summary": { "present": 12, "donated": 9 } }
```
`409 no_live_campaign` إن لم توجد حملة جارية (الواجهة تعرض: "الحملة ليست جارية الآن").

### 11.2 `GET /supervisor/donors`
قائمة متبرعي موقعه في الحملة الجارية.

| المعامل | الوصف |
|---|---|
| `q` | بحث بالاسم الأول أو الأخير |
| `status` | `attended` / `donated` |
| `limit`، `offset` | الصفحات، الأحدث تسجيلًا أولًا |

**عنصر القائمة (بلا هاتف):**
```json
{ "id": "…", "first_name": "سارة", "last_name": "ب", "blood_type": "A+",
  "status": "attended", "created_at": "…" }
```

### 11.3 `GET /supervisor/donors/summary`
عدّادات موقعه: `{ "present": 12, "donated": 9 }`.

### 11.4 `POST /supervisor/donors/check-phone`
**الجسم:** `{ "phone": "…" }` ← `{ "exists": true }`
لتنبيه ناعم من التكرار **دون منع** (قرار D-11). في الجسم لا في الرابط حتى لا يظهر الرقم في السجلات.

### 11.5 `POST /supervisor/donors` (إضافة متبرع)

**الجسم:**
```json
{
  "id": "c6a1…",                       
  "first_name": "سارة",
  "last_name": "بن علي",
  "phone": "0550000000",
  "blood_type": "A+",
  "consent_keep_phone": true,
  "consent_hero_name": true,
  "consent_photo": false,
  "consent_public_phone": false
}
```

| الحقل | إلزامي | قواعد |
|---|---|---|
| `id` | لا (يُنصح) | UUID يولّده العميل لمنع التكرار (انظر 11.6) |
| `first_name` | نعم | 1–40 حرفًا |
| `last_name` | لا | حتى 40 |
| `phone` | لا | 8–15 رقمًا بعد التطبيع |
| `blood_type` | لا | إحدى الثمانية |
| 4 موافقات | نعم (افتراضي `false` إن حُذفت) | منطقية |

**القواعد (تفاصيلها في `06`):**
1. الحالة الابتدائية `attended`، و`registered_by` من المستخدم، والموقع والحملة من السياق.
2. **`phone` موجود بلا `consent_keep_phone` ولا `consent_public_phone` ← `422 phone_requires_consent`.** (الواجهة تُرسل `null` ولو كتبه المشرف.)
3. **`consent_public_phone = true` يتطلب `phone` و`blood_type` ← وإلا `422 public_phone_requires_data`.**
4. تسجيل تدقيق `donor.create` (بلا بيانات شخصية).

**المخرجات:** `201` مع المتبرع (القسم 12.4).

### 11.6 الإعادة الآمنة (Idempotency)
معرّف العميل `id` يجعل **إعادة الإرسال بعد انقطاع الشبكة** آمنة:

| الحالة | الرد |
|---|---|
| المعرّف جديد | `201` + السجل |
| المعرّف موجود **لنفس المشرف والموقع والحملة** وبالمحتوى نفسه | `200` + السجل نفسه (لا تكرار) |
| المعرّف موجود لسجل مختلف أو لموقع آخر | `409 duplicate_id_conflict` |

### 11.7 `GET /supervisor/donors/{id}`
التفاصيل **مع الهاتف** (للمشرف في موقعه فقط). خارج النطاق ← `404`.

### 11.8 `PATCH /supervisor/donors/{id}`
**حقول مسموحة:** `first_name`، `last_name`، `phone`، `blood_type`، والموافقات الأربع. (**ليس** `status` هنا.)
**القواعد:**
- نفس قواعد الهاتف والموافقات في الإنشاء، مقيَّمة على **الحالة النهائية** بعد التعديل.
- **سحب الموافقة:** `consent_keep_phone` و`consent_public_phone` معًا `false` ← يجب إرسال `phone: null` (الخادم لا يمحوه بصمت، ويرد `422 phone_requires_consent` إن بقي).
- سحب `consent_public_phone` يزيل المتبرع فورًا من الطوارئ، وسحب `consent_hero_name` من الأبطال.
- **سحب `consent_photo`:** تحويله إلى `false` يحذف فورًا جميع الصور الفردية المرتبطة بهذا المتبرع في نفس المعاملة (`BR-CONSENT-07`، `BR-PHOTO-12`) ويضع ملفاتها في طابور الحذف `file_deletion_queue`.
- تدقيق `donor.update` بأسماء الحقول المتغيرة فقط.

### 11.9 `PUT /supervisor/donors/{id}/status`
**الجسم:** `{ "status": "donated" }` أو `"attended"`.
**القواعد:** الانتقال في الاتجاهين مسموح. `donated` ← تُملأ `donated_at`، والرجوع إلى `attended` ← تُمحى. **idempotent** (تكرار الطلب لا يضر). تدقيق `donor.status_change`.
**المخرجات:** `200` + المتبرع.

### 11.10 `DELETE /supervisor/donors/{id}`
حذف خطأ إدخال. **صور المتبرع الفردية تُحذف معه** وتُضاف ملفاتها لطابور الحذف. تدقيق `donor.delete`. `204`.

## 12. صور المشرف

### 12.1 `POST /supervisor/photos` (`multipart/form-data`)

| الحقل | إلزامي | الوصف |
|---|---|---|
| `file` | نعم | JPEG أو PNG أو WebP |
| `kind` | نعم | `general` أو `individual` |
| `donor_id` | عند `individual` | المتبرع من موقعه |
| `caption` | لا | حتى 200 حرف |

**القواعد:**
1. **الحد:** 5 ميغابايت قبل المعالجة، وإلا `413 file_too_large`.
2. **التحقق من المحتوى الفعلي** (الصيغة الحقيقية للملف لا الامتداد ولا ترويسة النوع)، وإلا `422 invalid_image` / `415`.
3. **المعالجة في الخادم (المرجع):** إعادة ترميز الصورة، **إزالة EXIF كاملًا** (بما فيه الموقع الجغرافي)، تصغير الضلع الأطول إلى نحو 1600 بكسل. (الواجهة قد تفعل ذلك أيضًا، لكن الخادم لا يثق بها.)
4. اسم الملف في التخزين **يولّده الخادم** (`uuid`)، ولا يُستعمل اسم العميل.
5. **`individual`:** المتبرع من نفس الموقع والحملة، **و`consent_photo = true`**، وإلا `422 photo_consent_missing`.
6. عند فشل حفظ السجل بعد رفع الملف: **يُحذف الملف** (لا ملفات يتيمة).
7. تدقيق `photo.upload`.

**المخرجات:** `201` + `{ id, kind, caption, url, donor_id, created_at }`.

### 12.2 `GET /supervisor/photos`
صور موقعه في الحملة الجارية (`limit`/`offset`).

### 12.3 `DELETE /supervisor/photos/{id}`
صور موقعه فقط. يحذف السجل ويضيف الملف لطابور الحذف. `204`.

# الجزء الرابع: واجهة الأدمن (`/admin`)

> **الشروط العامة:** أدمن نشط **و`mfa_verified`** (M). العمليات المعلَّمة **R** تتطلب تأكيدًا حديثًا (وإلا `403 reauth_required`).
> **قوائم الأدمن** ملتزمة بالحد الأقصى 100 لكل صفحة (لا تصدير). وتُراقب الطلبات المتكررة المفرطة.

## 13. الحملات

| النقطة | الصلاحية | الوصف |
|---|---|---|
| `GET /admin/campaigns` | `campaign:manage` | كل الحملات بكل حالاتها |
| `POST /admin/campaigns` | `campaign:manage` | إنشاء (غير منشورة، حالتها `upcoming`) |
| `GET /admin/campaigns/{id}` | `campaign:manage` | تفاصيل |
| `PATCH /admin/campaigns/{id}` | `campaign:manage` | تعديل (العنوان، `slug`، المحتوى، الغلاف، التاريخ، `is_published`) |
| `POST /admin/campaigns/{id}/set-current` | `campaign:manage` | تعيين الحملة الحالية |
| `POST /admin/campaigns/{id}/open` | `campaign:manage` | `upcoming → live` وتعيينها حالية تلقائيًا |
| `POST /admin/campaigns/{id}/revert` | `campaign:manage` + **R** | `live → upcoming` للتصحيح (بشرط عدم وجود متبرعين) |
| `POST /admin/campaigns/{id}/end` | `campaign:end` + **R** | إنهاء الحملة وتجميد الأرقام في `final_stats` |
| `DELETE /admin/campaigns/{id}` | `campaign:manage` + **R** | حذف |

**القواعد الأساسية:**
- `slug`: لاتيني صغير وأرقام وشرطات، فريد (`409 slug_taken`).
- **تعديل الحملة (`PATCH`):**
  - **منع إلغاء النشر:** يُمنع تحويل `is_published` إلى `false` إذا كانت الحملة جارية (`live`) ← يرد `409 invalid_state_transition` (`BR-CAMP-12`).
  - **تثبيت تاريخ الحملة:** يُمنع تعديل `campaign_date` بعد أن تصبح الحملة جارية (`live`) أو منتهية (`ended`) ← يرد `409 invalid_state_transition` (`BR-CAMP-14`).
- **تعيين الحالية (`set-current`):** في **معاملة واحدة** (إلغاء السابقة ثم تعيين الجديدة). مسموح لحملة منشورة فقط.
- **`open`:**
  - ينقل الحملة من `upcoming` إلى `live`.
  - **تُعيَّن الحملة حاليةً تلقائيًا (`is_current = true`) ضمن المعاملة نفسها** (`BR-CAMP-06`).
  - تتطلب أن تكون الحملة منشورة ولها موقع مشارك واحد على الأقل، وليست منتهية.
  - **حملة جارية واحدة فقط:** إن وُجدت حملة أخرى جارية حاليًا، يُرفض الطلب بـ `409 invalid_state_transition` (`BR-CAMP-06`، `BR-CAMP-07`).
- **`revert`:** مسموحة **فقط إن لم يُسجَّل أي متبرع** في الحملة، وإلا `409 invalid_state_transition` (`BR-CAMP-08`). وتتطلب تأكيدًا حديثًا (R).
- **`end`:** من `live` فقط (أي حالة أخرى ← `409 invalid_state_transition`، `BR-CAMP-09`). معاملة واحدة ذرية: تحسب الأرقام وتخزّنها في `final_stats` وتغيّر الحالة إلى `ended` وتسجّل `ended_at` وتدوّن `campaign.end`. تعيد الأرقام النهائية. إعادة الاستدعاء على منتهية تُحدّث الأرقام **ما لم** تُخفَ الهوية (`409 campaign_purged`).
- **`DELETE`:** فقط إن لم توجد تعهدات أو متبرعون أو صور، وإلا `409 in_use`.
- **المنتهية:** لا تعود `live` ولا `upcoming` (`409 invalid_state_transition`، `BR-CAMP-11`).
- **المحتوى (Markdown):** يُخزَّن كما هو، ويُعقَّم ويُحوَّل إلى HTML في الخادم عند العرض (D-70).

**مخرجات `end`:**
```json
{ "pledges": 143, "present": 61, "donated": 52, "heroes": 38,
  "by_site": [ { "site_id": "…", "name": "…", "pledges": 70, "present": 30, "donated": 26 } ],
  "frozen_at": "…" }
```

### 13.1 مواقع الحملة

| النقطة | الوصف |
|---|---|
| `GET /admin/campaigns/{id}/sites` | المواقع المشاركة |
| `PUT /admin/campaigns/{id}/sites/{site_id}` | إضافة أو تعديل مشاركة: `start_time`، `end_time`، `supervisors_text`، `notes` |
| `DELETE /admin/campaigns/{id}/sites/{site_id}` | إزالة المشاركة. `409 in_use` إن وُجد متبرعون |

**القاعدة:** `end_time > start_time` إن وُجدا.

## 24. متطلبات الاختبار

> الصياغة التفصيلية في `07-test-cases.md`.

| الفئة | المطلوب |
|---|---|
| **تغطية المسارات** | اختبار آلي يمر على كل مسار مسجّل ويتحقق أنه إمّا عام مصرّح به أو له صلاحية معلنة |
| **العقد (Contract)** | مقارنة المخرجات الفعلية بمخططات الاستجابة، وفحص **غياب الحقول السرية** (`password_hash`، `totp_secret_enc`، `registered_by` للعامة) |
| **الحقول الزائدة** | كل نقطة كتابة ترفض حقلًا غير معرّف بـ `422 unknown_field` |
| **الحقول المحجوزة** | مشرف يرسل `site_id` أو `status` ابتدائيًا ← `422` وحدث تدقيق |
| **الإعادة الآمنة** | إرسال `POST /supervisor/donors` بنفس `id` مرتين ← `201` ثم `200`، سجل واحد |
| **التعهد المكرر** | ردّان متطابقان `204`، سجل واحد |
| **الأبطال والطوارئ** | تُرجع من وافق وتبرّع فقط، ولا هاتف في القائمة |
| **التقييد** | `limit > 100` ← `422`، ولا `limit=all` |
| **الأخطاء** | كل رمز في القسم 3.2 له اختبار واحد على الأقل بالشكل الموحّد |
| **الذاكرة المؤقتة** | ترويسات `Cache-Control` صحيحة، و`no-store` على الطوارئ وكل المصادَق عليه |
| **CSRF** | كل طلب كتابة مصادَق بدون `X-CSRF-Token` ← `403 csrf_failed` |
| **الصور** | ملف ليس صورة (امتداد مزيّف)، ملف كبير، EXIF مُزال في الناتج، فشل السجل يحذف الملف |
| **الإنهاء** | `end` يجمّد الأرقام، وبعده المشرف يتلقى `409` أو `404` ويفقد القراءة والكتابة |

## 26. ملخص

- **مسارات واضحة:** `/public` للزائر، `/auth` و`/me` للحساب، `/supervisor` للميدان، `/admin` للإدارة.
- **الخادم يشتق النطاق:** لا `site_id` ولا `campaign_id` من المشرف، والحقول المحجوزة تُرفض وتُدوَّن.
- **عقد أخطاء موحّد** برموز ثابتة، والواجهة تترجمها لرسائل عربية.
- **إعادة آمنة:** معرّف المتبرع من العميل (`201` ثم `200`)، والتعهد المكرر بردّ متطابق.
- **الخصوصية في التصميم:** الهاتف في التفاصيل فقط، والطوارئ بخطوتين وبلا تخزين مؤقت، ومفاتيح إيقاف بمردود `503`، ولا تصدير (حد 100 لكل صفحة).
- **الصور:** معالجة في الخادم تُزيل EXIF وتتحقق من المحتوى الحقيقي، وسحب الموافقة يحذف الصور تلقائيًا.
- **الإنهاء والإخفاء:** `end` معاملة واحدة تجمّد الأرقام، والإخفاء أمر CLI لا نقطة HTTP.

### 27.3 الفروق الجوهرية بين الطبقتين

1. **الترويسات والأمان:** صفحات HTML تُرجع `Content-Type: text/html; charset=utf-8` وتلتزم بـ CSP يمنع أي سكربت مضمن أو خارجي (`script-src 'self'`). بينما الـ API يرجع `application/json` وتلتزم بـ `extra="forbid"`.
2. **استدعاء البيانات:** صفحات HTML العامة تنادي **الخدمات مباشرة** لسرعة التوليد وتوفير وسوم OG لروبوتات واتساب وفيسبوك. أما اللوحات التفاعلية (المشرف والأدمن) فتستخدم وحدات JavaScript القياسية لاستدعاء واجهة `/api/v1` بالكوكي ورمز `X-CSRF-Token`.
